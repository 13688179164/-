# GOODWORK 古德車房 · 悬浮生态财务工作台

一个悬浮在深空中的透明玻璃立方体微缩世界。岛上有雪山、蜿蜒河流、悬空瀑布、湖泊、森林、草地、微型动物与漂浮云朵，中心是双层玻璃幕墙的 **GOODWORK 古德車房**。

点击车房会触发三段缓动运镜、场景虚化与右侧滑入的报销表单，形成从「三维世界」到「财务工作流」的完整闭环。

> 注：当前运行环境是 Linux 工作区，项目位于 `/workspace/goodwork-garage`。如需按原计划放在 D 盘，只需将整个 `goodwork-garage` 文件夹复制到 `D:\goodwork-garage`，运行方式完全一致。

## 1. 快速开始

### 方式 A：Node.js 静态服务器（推荐）

要求 Node.js 18+，无需安装任何依赖。

```bash
cd goodwork-garage
npm start
```

打开 `http://localhost:5173`。

也可以直接运行：

```bash
node server.mjs
# 指定端口
PORT=8080 node server.mjs
```

### 方式 B：Python 静态服务器

```bash
cd goodwork-garage
python3 -m http.server 8080
```

打开 `http://localhost:8080`。

> 必须通过 HTTP 服务访问，不能直接双击 `index.html`。项目使用原生 ES Modules + importmap，`file://` 协议会因模块路径限制而无法加载。

### 浏览器建议

- Chrome / Edge / Safari 最新版，需支持 WebGL2。
- 首次点击/按键后才会启用 WebAudio 氛围声（浏览器自动播放策略限制）。
- 推荐独立显卡或较新的集成显卡；移动端会自动降低粒子数量与像素比。

### 二级报销工作台

点击车房后进入新版 **GOODWORK 报销工作台**：

1. **当日看板**：顶部日期可切换，三列固定为「待报销 / 已报销 / 已补充附件」。直接拖拽卡片即可在列间流转，卡片整张荧光黄绿的为待报销（进行中）任务。
2. **筛选查询**：看板上方提供「申请人 / 是否有发票 / 申请日期区间」三种查询条件，可任意组合筛查三列记录；「今天 / 本月 / 重置」可快速切换范围。顶部日期切换与筛选日期联动。
3. **未完成占比**：顶部超大细体数字显示「待报销金额 / 当前范围总金额」，下方三段式进度条按金额拆分待报销、已报销、已补充附件三个状态。
4. **新增报销**：填写报销人员、金额、部门、报销分类、申请时间、是否有发票、内容，可上传多张图片或文档。部门和分类联动；分类为「配件」且金额 ≥ ¥3,000 时出现「高额配件成本属性」，需要选择是否跨月、备货成本。
5. **编辑 / 删除**：卡片右下角提供编辑与删除；删除前有二次确认。所有修改自动写入本机。
6. **卡片折叠**：点击卡片主体或右下角折叠按钮，可平滑折叠 / 展开报销内容，折叠状态同样写入本机。
7. **当日已处理待报销**：顶部独立显示栏汇总今天从「待报销」流转为「已报销」的金额与笔数，并列出最近几笔处理记录；点击「导出本月日报」可导出当月每日汇总与逐笔处理明细（含时间）的 Excel。
8. **发票追踪**：自动从「已报销」中抓取「有发票」的记录，生成未取得发票清单，展示申请人、申请时间、报销内容、凭证附件与总金额；点击「已取得发票」后自动归档到已取得发票栏。支持按申请人和时间范围筛选。
9. **底部金额**：展示当前筛选范围的待报销总额、已报销总额与已补充附件金额。
10. **统计与导出**：右上角导出栏可选择时间范围（今天 / 本周 / 本月 / 全部或自定义），生成详细统计报告，并导出包含 5 个基础工作表的 Excel：
    - 报销明细（部门、报销分类、时间、申请人员、内容、报销状态、报销金额、是否有发票、高额配件成本属性、附件）
    - 部门分类统计（含每个部门的小计）
    - 员工报销统计
    - 总览报告
    - 附件清单
    当时间范围内存在附件时，会额外生成「附件预览」工作表：图片凭证以缩略图直接嵌入「报销明细」的附件列，点击蓝色的「点击查看 N 个附件」可跳转到附件预览页查看全尺寸图片；文档类附件在预览页列出文件名、大小与说明，「附件清单」中也提供逐条「查看」跳转。
11. **月度财务报表**：在统计报告右上角点击「月度财务报表」，可按月生成与车房现金流量表图片同版式的预览表格，并导出带合并单元格、边框、金额格式的 Excel。成本按报销分类自动映射到「维修、保养、钣喷、洗车、美容、贴膜、改装、门店运维、线上运营」业务列与图片中的成本项目行；统计口径为当月已报销成本（含已补充附件）。
12. **腾讯云开发多设备同步**：顶部「云同步」入口可配置云开发环境 ID 与团队工作区账号；登录后任务、报销状态、发票追踪、已处理日报和附件会同步到 CloudBase。修改后约 1.5 秒自动上传，并实时监听其他设备的变化；附件上传到云存储，其他设备按需下载。未连接或离线时仍以本机数据继续工作。
13. **本地持久化**：任务写入 `localStorage`，附件二进制写入 `IndexedDB`，刷新不丢失；首次打开预置 4 条可编辑示例任务。

#### 关于自动写入 D:\车房凭证

浏览器安全策略不允许网页静默写入本机任意路径。工作台采用 **File System Access API** 实现最接近“自动写入”的方案：

- 首次点击导出栏右下角的「绑定」，在系统弹窗中选择 **D:\**（或已有的 `D:\车房凭证`）。
- 工作台会自动使用/创建 `车房凭证` 文件夹，并保存该目录授权。
- 此后保存带附件的报销时，附件会自动写入该文件夹；仍可点击「同步」补写历史附件。
- 文件命名：`日期_报销人_金额_部门`，多个附件追加 `_2`、`_3` 后缀并保留原始扩展名。
- 若浏览器不支持目录授权（如 Firefox），附件会稳定保存在本机 IndexedDB，可在报销编辑抽屉中逐个下载。
- 刷新后如浏览器要求重新授权，导出栏会显示「恢复授权」，点击一次即可继续自动写入。

> 该授权必须由用户主动选择目录一次；这是浏览器的安全限制，而非工作台逻辑缺失。部署在 HTTPS 的页面上使用 Chrome / Edge 可获得完整体验。

#### 关于腾讯云开发多设备同步

工作台通过 **腾讯云开发 CloudBase Web SDK** 实现团队共享工作区：

- 顶部「云同步」→ 填写云开发环境 ID、团队工作区账号邮箱与密码，登录后开始同步。
- 所有设备使用同一个工作区账号，因此共享同一份台账与附件；账号密码不会写入代码或 `localStorage`，只保存 SDK 的登录态。
- 云端数据位置：数据库集合 `goodwork_workspaces` 的 `team` 文档，包含任务、状态、发票追踪、已处理事件；附件在云存储 `goodwork/team/`。
- 实时同步：本地修改约 1.5 秒后自动上传；通过数据库 `watch` 监听其他设备的变化。关闭「自动实时同步」后，可使用「上传本机到云端 / 从云端拉取 / 同步附件」手动控制。
- 冲突策略：按 `rev` 与 `updatedAt` 做最近写入优先；其他设备的新版本会先应用到本机，避免直接覆盖。团队多人同时编辑同一条记录时仍可能出现后写覆盖，请避免同时修改同一笔报销。
- 附件：新附件保存后自动上传；其他设备在下载、导出 Excel 或写入 D 盘时按需从云端下载并缓存到 IndexedDB。D 盘写入状态属于本机，不会同步给其他设备。
- 离线：云连接失败时工作台继续使用本机数据，恢复网络后可手动上传或拉取。

**首次配置清单**

1. 在腾讯云开发控制台创建环境，复制环境 ID。
2. 开启「邮箱密码登录」；如启用了邮箱验证，先完成账号验证或由管理员创建团队账号。
3. 创建数据库集合 `goodwork_workspaces`，权限选择「仅创建者可读写」。
4. 开启云存储；附件会保存到 `goodwork/team/`。
5. 在「安全域名」中加入当前站点域名（部署后的 `*.traesite.cn` 域名，或本地开发时的 `localhost:5173`）。

> 团队共享模式使用一个共享账号，适合小型门店财务工作区；不要把账号密码发送给工作区以外的人。当前使用单个工作区文档保存全部台账，适合数百到数千条记录规模；如果历史数据长期增长到很大，可再按月份拆分云端文档。

## 3. 功能实现清单

### 3.1 场景

- 悬浮岛：程序化地形高度场、岩层断崖、悬挂根系、岛底漂浮碎岩与冷光晕。
- 雪山：程序化多峰高度场，顶点色融合岩石 / 积雪，含山脊噪声与雪线。
- 水体：蜿蜒河道、圆湖、石质溢流槽、双层动态瀑布、木栈桥、小木船、睡莲。
- 植被：35 棵树（阔叶 / 松树 / 樱树）、约 200 组灌木、草簇、花丛、蘑菇、苔石。
- 动物：两只微缩鹿、三只环湖飞鸟、蝴蝶。
- 大气：6 组黏土云、16 组薄雾、深空星野、远景行星、散景光斑。

### 3.2 车房建筑

- 两层玻璃幕墙、黄铜竖挺、深色石材基座、门厅雨棚与入口门廊。
- **屋顶金边主招牌**、**左侧竖式灯箱**、**右侧双面侧招**、入口门牌与品牌门饰。
- 一层展厅：双柱举升机、深酒红 GT 跑车、接待台、财务 OS 屏幕、工具柜、轮胎、绿植与技师。
- 二层财务工作区、暖光灯带、品牌背光墙与楼上设备间。
- 配套建筑：财务室、仓库、员工宿舍，以及配送车、停车牌、庭院路灯、票据箱、审批终端。

### 3.3 四季系统

默认每 **18–28 秒**随机切换，也可手动点选。过渡时长约 2–3 秒。

| 季节 | 天气粒子 | 环境变化 |
| --- | --- | --- |
| 春 | 樱瓣 1,100 | 暖光、嫩绿、樱花 |
| 夏 | 雨丝 1,200（LineSegments 单批次） | 高亮冷光、深绿、雨噪氛围声 |
| 秋 | 橙叶 1,050 | 琥珀光、橙叶、薄雾 |
| 冬 | 细雪 1,300 | 冷蓝光、地面积雪、屋顶/树冠覆雪、湖岸冷色 |

- 天气系统常驻内存，切换时只插值 `uOpacity`；一个季节只有 1 个天气 draw call。
- 独立环境浮尘 280 粒（加色混合、缓升闪烁），与季节特效并行。
- 焊接火花 140 粒（移动端 84），使用独立的 Points 更新位置与颜色。

### 3.4 22 类可交互元素

主建筑、主招牌、竖式灯箱、侧招、举升机车辆、票据箱、审批终端、停车牌、路灯、配送车、环道车流、环岛樱树、镜湖、悬空瀑布、雪峰、微缩鹿群、财务室、仓库、员工宿舍、NPC、漂浮云朵、薄雾。

- 悬停：鼠标指针变化、金色光环、世界空间标签高亮、跟随鼠标提示浮层、WebAudio 轻音。
- 点击：右侧档案面板展示分类、参数、实时档案与标签；部分入口提供「进入车房 / 取票 / 审批 / 派发任务」等操作。
- 拾取防遮挡：玻璃标记 `userData.glass`，射线优先返回非玻璃命中，因此在玻璃外可以直接点击内部举升机跑车；玻璃本身仍可点击进入车房。

### 3.5 NPC 系统

- 4 名员工：林晓（财务）、陈默（仓储）、苏禾（接待）、周野（技术服务）。
- **32 × 22 导航网格**，8 向 A*，禁止斜穿墙角。
- 视线路径平滑（string pulling），到达目标或遇障时重新规划。
- 同伴分离力、卡住检测与重规划。
- 步行腿部 / 手臂反相摆动、头部环视、朝向最短角插值、抵达后自动转入 idle/巡逻。
- 任务链：林晓取票送到车房、提交后前往审批终端，审批后回到车房。

### 3.6 车流与行人

- 8 台环道车辆使用 `InstancedMesh`：车身（实例色）、座舱玻璃、四轮、前灯、尾灯，共 5 个绘制批次并逐帧更新实例矩阵。
- 20 名行人使用 2 个 `InstancedMesh`（身体 + 头部），沿三条步道循环并带轻微上下浮动。
- 金色路缘、合并为单批次的环道虚线、程序化石材广场、铜章与引导牌。

### 3.7 镜头与业务衔接

- 点击车房：相机沿三个关键帧推进（0.95s / 0.95s / 1.05s，`easeInOutCubic/Quint`），场景在约 0.46s 后开始 CSS 景深虚化；报销工作台随后全屏展开。
- 关闭工作台 / Esc：镜头缓动回到进入前位置，虚化与光晕同步恢复。
- 工作台内部为独立的 DOM 面板，增删改、拖拽与表单不会阻塞 3D 渲染循环。

### 渲染与性能

- Three.js `r164` 本地 vendor，原生 ESM + importmap，无构建步骤、无 CDN 依赖。
- `EffectComposer`：RenderPass + UnrealBloomPass + OutputPass（ACES Filmic）。
- 像素比上限 1.75；移动端降低体力消耗更大的粒子数量。
- **1 盏平行光投影**，阴影贴图 1024²；首帧后冻结静态阴影贴图（NPC / 行人 / 车流默认不投影），显著降低逐帧阴影 draw call。
- 只在必要处开启透明材质和逐帧实例矩阵更新。
- 在地道路标线、幕墙竖挺、品牌灯带等处尽量合并几何；天气每种只有 1 个 Points / LineSegments。
- 桌面测试环境（Chrome + SwiftShader 软件渲染）约 690 个绘制批次、约 10.7 万三角形、1,520 个粒子；真实硬件 GPU 下帧率更高。
- 所有纹理（深空、招牌、草地、石材、水纹、行星、雾、铜章等）均在运行时程序化生成，不依赖外部图片。

## 5. 开发说明

### 修改季节

编辑 `src/core/config.js` 的 `SEASONS` 数组：雾色、雾密度、半球光、主光、轮廓光、环境光、曝光、Bloom、植被色、水体色、玻璃色、积雪强度等。`src/systems/seasons.js` 会自动插值并驱动材质。

### 修改报销部门 / 分类 / 示例任务

- 部门与分类映射：`src/core/reimburseConfig.js` 的 `DEPARTMENTS` / `DEPT_CATEGORIES`。
- 月度财务报表的业务单元、成本项目行与映射规则：同文件的 `BUSINESS_UNITS` / `MONTHLY_COST_ROWS` / `mapCostToStatement`。
- 首次打开的示例任务：同文件的 `createSampleTasks()`（只会在本地没有任务数据时生成）。
- 报销工作台界面与逻辑：`src/ui/reimburse.js`；样式：`reimburse.css`。
- 本地数据键：任务 `goodwork.reimburse.tasks.v3`，设置 `goodwork.reimburse.settings.v3`，已处理待报销事件 `goodwork.reimburse.processed.v1`，云同步设置 `goodwork.cloud.settings.v1`，设备标识 `goodwork.cloud.device.v1`；附件在 IndexedDB `goodwork-reimburse` 的 `attachments` 表。
- 云同步逻辑：`src/core/cloudSync.js`；数据库集合 `goodwork_workspaces`，工作区文档 `team`，附件目录 `goodwork/team/`。
- 发票追踪状态保存在任务的 `invoiceReceived` / `invoiceReceivedAt` 字段；折叠状态保存在 `collapsed` 字段；附件云文件 ID 保存在 `attachment.cloudFileId`。
- 统计 Excel 使用按需加载的本地 `vendor/exceljs.min.js` 生成；导出时会把图片附件转成缩略图嵌入附件列，并追加「附件预览」工作表。`vendor/fflate.min.js` 用于在 XLSX 包内写入内部跳转链接。
- 月度财务报表与本月日报使用按需加载的本地 `vendor/xlsx.full.min.js`（xlsx-js-style），不依赖 CDN。

### 修改招牌 / 文案

- 招牌文字与排版：`src/core/textures.js` 中 `makeMainSignTexture` / `makeVerticalSignTexture` / `makeBladeSignTexture`。
- 建筑铭牌：`makeBuildingSignTexture`。
- 档案面板文案：`src/core/archive.js`。
- 表单字段 / 票据数据：`src/core/config.js` 的 `EMPLOYEES` / `RECEIPTS` / `EXPENSE_TYPES`。

### 增加可交互元素

1. 在对象 mesh 上设置 `userData.interactiveKey = 'yourKey'`（玻璃请加 `userData.glass = true`）。
2. 在 `src/core/archive.js` 增加档案文案。
3. 在 `src/systems/interaction.js` 的 `config` 中增加锚点、光环半径和标签开关。
4. 如需要点击动作，在 `src/ui/ui.js` 的动作里增加分支，并在 `src/main.js` 的 `handleAction` 中处理。

### NPC 寻路

- 导航数据由 `src/world/terrain.js` 的水域、建筑矩形与 `src/world/island.js` 的树干障碍共同生成。
- `NPCSystem` 在 NPC 达到目标或卡住时重新计算 A*，并做视线平滑；不需要每帧计算网格。
- 新增 NPC 时扩展 `EMPLOYEES` 并在 `NPCSystem` 中自动创建。

### 粒子

- `src/systems/particles.js` 中每种天气是常驻的单个 Mesh，季节切换仅改 `uOpacity`。
- 增加天气类型时沿用 `WeatherPoints` / `RainSystem` 的结构，避免创建/销毁几何体。

## 6. 已知说明

- 默认情况下报销数据保存在本机浏览器：任务在 `localStorage`，附件在 `IndexedDB`，刷新或重启浏览器不会丢失；清理站点数据会删除这些记录。启用云同步并登录后，任务、状态与附件会上传到用户自己配置的腾讯云开发环境。
- 未启用云同步时，数据按浏览器 / 设备隔离；启用后，使用同一工作区账号的设备共享同一份台账与附件。可使用 Excel 导出做额外备份。
- 3D 场景中的票据箱 / 审批终端与 NPC 任务链作为空间叙事保留；二级报销工作台的数据以看板与云同步结果为准。
- 自动写入 `D:\车房凭证` 依赖浏览器 File System Access API。首次必须由用户主动选择一次 D 盘目录；之后在该授权有效期内自动写入，权限过期时点击「恢复授权」即可。Firefox 等不支持该 API 的浏览器会将附件保存在 IndexedDB 并提供下载。
- 中文排版依赖系统中文字体（Noto Sans/Serif CJK、苹方、微软雅黑等）；无中文字体时浏览器会回退到默认字体。
- 声音需要用户首次交互后才能播放；不交互时保持静音是浏览器策略。
- 云同步需要用户自行创建腾讯云开发环境并完成安全域名、登录方式、数据库集合与云存储配置；应用内不包含环境 ID 或账号密码。云开发的用量与费用由对应的腾讯云账号承担。
