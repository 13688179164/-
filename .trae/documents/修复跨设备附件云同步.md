# 修复跨设备附件云同步

## Context

当前报销任务只把附件名称、大小、类型等元数据同步到 PostgreSQL；`cloudSync.js` 的上传函数固定返回空字符串，下载函数直接抛出“不支持”。因此其他设备只能看到附件记录，导出月度 Excel 时无法取得文件本体并显示“附件缓存缺失”。目标是让新附件自动上传，其他设备按需下载、缓存并正常导出，同时支持原设备补传历史附件。

## 实施方案

### 1. 接入现有 CloudBase 云存储

修改 `src/core/cloudSync.js`，保留现有纯 fetch PostgreSQL 业务同步，仅为附件懒加载项目已有的 `vendor/cloudbase.full.js`。

- 使用现有环境 ID、Publishable Key 和新网关 `apiOrigin` 初始化存储实例，并完成匿名鉴权。
- 使用 PG Bucket `goodwork`，对象路径统一为 `team/<附件ID>.<原扩展名>`。
- `uploadAttachment()` 调用 `app.storage.from('goodwork').upload()`，保留 MIME，允许重试覆盖，返回 `pg:team/...` 写入现有 `cloudFileId`。
- `downloadAttachment()` 对 `pg:` 文件调用 Bucket `download()` 并返回 Blob；保留 `cloud://` 旧文件的临时 URL 下载兼容分支。
- 上传或权限失败时保留空 `cloudFileId` 并报告真实错误，不伪装成功，不阻塞本地报销保存。

### 2. 恢复附件上传流程及元数据回写

在 `src/core/cloudSync.js` 实现一个供单任务与批量补传共用的上传循环：

- 仅处理尚无 `cloudFileId` 的附件，通过 `getAttachmentBlob(meta.id)` 读取 IndexedDB 文件。
- 上传成功后立即写回 `meta.cloudFileId`，并更新对应任务 `updatedAt`，保证其他设备轮询能发现变化。
- 单任务保存后：调用 `onAttachmentsUploaded()` 持久化，再立即 `pushNow()` 上传附件元数据，即使关闭自动同步也不丢 fileID。
- 批量补传：将修改后的任务通过现有 `applyState()` 回写工作台和 localStorage，再统一推送；用 `try/finally` 释放上传锁。
- 手动“同步附件”显示实际上传/失败数量；本地已无 Blob 且云端从未上传的旧附件明确无法自动恢复。

### 3. 修复全局单例回调

修改 `src/ui/reimburse.js` 构造函数，在复用 `window.__cloudSync` 后统一重绑：

- `getAttachmentBlob: id => readAttachmentBlob(id)`
- `onAttachmentsUploaded: () => this.persistTasks()`

若实例已经连接，补触发一次静默附件同步，避免全局实例早于工作台初始化而漏传历史文件。现有 `ensureAttachmentBlob()` 会在本地无缓存时下载并回写 IndexedDB，无需改 Excel 导出链。

### 4. 防止同步覆盖附件元数据

将 `connectData()` 中现有的 `goodwork_attachments` 拼装逻辑复用到：

- `pollTick()`：检测到远端任务更新时补拉附件；读取失败则放弃本轮合并，不能用空附件列表覆盖本地。
- `pushNow()` 的推送前合并：为远端任务补齐附件元数据，避免远端较新的任务在合并后丢失附件。

继续以 `goodwork_attachments.cloud_file_id` 为主、`goodwork_tasks.cloud_file_ids` 为旧数据兜底；无需新增业务表或把 Blob/Base64 存入 PostgreSQL。

### 5. 缓存版本与部署

递增 `cloudSync.js`、`reimburse.js` 及 `main.js`/`index.html` 中受影响的 `?v=` 版本号，沿用静态站 ID `37l9gib3n8sziipttw9` 部署，并核验线上文件包含新逻辑。

## 验证

1. 执行 `node --check` 检查修改文件，并用 Node/浏览器环境测试 SDK 初始化、Bucket 上传和下载返回值。
2. 用测试图片和 PDF 验证：上传后云存储存在文件，数据库 `cloud_file_id` 与 `cloud_file_ids` 已更新，下载内容与原件一致。
3. 模拟无 IndexedDB 缓存的新设备：拉取任务后可下载附件，月度 Excel 的图片预览和文档附件不再显示“附件缓存缺失”。
4. 验证原设备历史附件补传、上传完成后刷新仍保留 fileID、另一台已打开设备轮询后附件不丢失。
5. 验证断网时本地保存不受影响，恢复后可重试；若 Bucket 或匿名权限未配置，通过真实 smoke test 定位并完成必要配置后再验收。
